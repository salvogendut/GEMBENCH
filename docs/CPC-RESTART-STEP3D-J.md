## Protocol prerequisite and emulator fix

The [M4 developer reference](https://www.spinpoint.org/cpc/m4info.txt), updated
2024-11-27, documents extended READDIR and pathname FSTAT. The local M4ROM
`ls_loop` and `LongName` confirm how the firmware consumes their results;
these are read-only references, not build dependencies.

The original 15-command real-M4 probe demonstrated two emulator defects:
READDIR with a name limit of 64 returned the same truncated `>EIGHTCH` legacy
record as no-argument READDIR; all FSTAT requests returned empty frames without
status or metadata. GETPATH and OPEN/FSIZE/CLOSE controls worked. It reported
BLOCKED with exit 2, never successful empty directories.

1984 now implements extended READDIR and pathname FSTAT, using the real FAT
entry's short alias, long name, attributes, modification date/time and 32-bit
size. Shared FAT listing/lookup validates LFN chains and rejects malformed
sequence-zero chains. Legacy no-argument catalog formatting is unchanged.
Host-directory tests use real host size/time/attributes; long host names have
no invented DOS aliases. Emulator code remains in 1984, not in this BSD repo.

The unchanged protocol reproducer now passes: full `>EIGHTCHR`, proper
directory/file metadata, explicit missing-file error, `BIG.BIN` size 74,565,
root restoration, response bounds and bank/IFF/lock preservation.
All 45 existing context checkpoints pass in the same run.

## Shared policy, CPC binding

The existing shared `fsctx_policy.inc` still owns handle generations, implicit
owner validation, per-context storage, activation, publication and <=4-entry
batches. CPC adds FIRST/NEXT hooks in `kernel/kc/cpc_fsdir.inc`, selected only
by the private `CPC_FS_DIRECTORY` composition.

Each 64-byte opaque context cursor stores a tagged 16-bit ordinal and its
normalized path. After activation changes the device directory, the adapter
restarts and replays to that context's ordinal. Within a single batch it reuses
the live device cursor. File reads and other owners may change M4 state without
losing the logical enumeration position. Path changes invalidate an old cursor.

Each returned entry has the real FSTAT short alias, all attribute bits and
four size bytes. The response/command/private-entry buffers are separate from
the caller's transfer buffer. Cleanup, stale handles and ownership use the
shared code; no private replacement ownership or batching policy was added.

An optional `FSCTX_DIRECTORY_STATUS()` hook distinguishes CPC errors from EOF.
Its default remains constant OK, preserving MSX behavior and generated bytes.
A failed partial batch retains its completed prefix/count and last published
cursor; errors are not converted to successful EOF. Native tests execute this
actual shared policy with an error-injecting directory backend.

The base 3D-I variant intentionally still rejects directory operations. The new
`fsctx-directory` variant enables operations 5, 6 and 14. Writes (9) and
free-space (10) remain unsupported. No public capability was advertised.

## Deliberate limits and next boundary

- Enumeration replay is capped at 1,024 entries per activation. Exceeding the
  bound returns FULL, not EOF. Across calls replay can be quadratic; this is
  not a GUI responsiveness benchmark. A live batch avoids repeated replay.
- Display names are limited to 63 printable ASCII characters; unsupported names
  fail explicitly. Canonical aliases currently accept uppercase letters,
  digits, underscore, hyphen and tilde, within 8.3. Directory path components
  retain 3D-I's narrower rules. This is not the complete FAT namespace.
- Host-backed long filenames without real short aliases are unsupported by this
  CPC binding. Image-backed aliases are taken from FAT, not invented.
- Listing is not a snapshot during directory mutation; callers restart FIRST.
  Native empty responses retain M4's EOF semantics; explicit transport/FSTAT/
  activation failures are errors. Corrupt media and all firmware error variants
  have not been exhaustively qualified.
- Arbitrarily long FSTAT replies, Unicode and real-board firmware behavior are
  not qualified. Independent M4/Albireo confirmation remains desirable;
  konCePCja's current FSTAT shape is incompatible (source evidence), while
  Arnold/Caprice32 still lack a qualified permitted storage path. See the
  [emulator strategy](CPC-EMULATOR-TEST-STRATEGY.md).

Next is complete filesystem/service and public SDK/module composition, resolving
these bounds as required by real applications before claiming parity. The
production adapter gate remains open before the first shared-core application
window, desktop integration and application parity. No raw FAT walker, raw
writes or hidden catalog-index workaround was introduced.
